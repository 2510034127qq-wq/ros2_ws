# 接手文档 05 · 构建运行调试手册

> 本篇是动手实操：从零编译、启动仿真、健康检查、采集、排错。
> 命令均假设工作区在 `/home/hanchen/ros2_ws`，环境 ROS 2 Humble + Gazebo Classic 11。
> 注：可在对话里用 `! <命令>` 让需要交互的命令直接在会话里跑。

## 1. 每个新终端的固定开头

```bash
cd /home/hanchen/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```
若 `install/setup.bash` 不存在 → 还没编译，先做第 2 步。

## 2. 首次编译（顺序很重要）

```bash
cd /home/hanchen/ros2_ws
source /opt/ros/humble/setup.bash

# 检查系统依赖（可选）
rosdep check --from-paths src/thermal_robot --ignore-src
# 缺啥就装：rosdep install --from-paths src/thermal_robot --ignore-src -r -y

# ① 接口包必须最先编（其它包要 import 它的消息）
colcon build --packages-select thermal_interfaces
source install/setup.bash

# ② 再编其余 7 个包
colcon build --packages-select \
  g1_description thermal_sensor_sim signal_preprocessor \
  thermal_field_reconstructor thermal_gradient_processor \
  thermal_motion_controller thermal_bringup
source install/setup.bash

# 确认 8 个包都在
colcon list
```

改了某个包后单独重编：`colcon build --packages-select <包名> && source install/setup.bash`。
**改了 `.msg/.srv` → 必须先重编 `thermal_interfaces` 再编下游。**

> 重要：`src/` 是唯一真相。`install/` 可能是旧的——跑之前若改过代码，务必重编。

## 3. 启动仿真

完整 GUI（Gazebo + RViz）：
```bash
ros2 launch thermal_bringup sim_nav_slam_launch.py use_rviz:=true use_gzclient:=true
# 等价简写：
ros2 launch thermal_bringup sim_nav_slam_launch.py
```
无界面（远程/采集/评测）：
```bash
ros2 launch thermal_bringup sim_nav_slam_launch.py use_rviz:=false use_gzclient:=false
```
指定 world + scenario：
```bash
ros2 launch thermal_bringup sim_nav_slam_launch.py \
  use_rviz:=false use_gzclient:=false \
  world_file:=$PWD/src/thermal_robot/thermal_bringup/worlds/thermal_scene_mixed_rooms.world \
  scenario_file:=$PWD/src/thermal_robot/thermal_bringup/config/scenarios/dynamic_waypoint_random_sources.yaml
```
看可用参数：`ros2 launch thermal_bringup sim_nav_slam_launch.py --show-args`

**启动时序**（见 `01`）：RViz 约 20s 后才出现；管线约 18s 起；采集等 25-30s 后再开。

## 4. 启动后健康检查

```bash
# 节点/话题/服务/动作
ros2 node list
ros2 topic list
ros2 action info /navigate_to_pose

# Nav2 lifecycle 应为 active
ros2 lifecycle get /planner_server
ros2 lifecycle get /controller_server
ros2 lifecycle get /bt_navigator

# 一键 Nav2 健康检查
python3 src/thermal_robot/scripts/nav2_health_check.py --timeout 20
```

话题频率（各看 5-10s 后 Ctrl+C）：
```bash
ros2 topic hz /sim/thermal_raw     # ~10Hz
ros2 topic hz /thermal/filtered    # ~10Hz
ros2 topic hz /thermal/field       # ~10Hz
ros2 topic hz /thermal/map         # ~5Hz
ros2 topic hz /thermal/sources     # ~5Hz
ros2 topic hz /thermal/gradient    # ~10Hz
ros2 topic hz /odom                # ~20Hz
ros2 topic hz /scan                # ~10Hz
ros2 topic hz /cmd_vel             # ~10Hz（控制中时）
```

查热场摘要：
```bash
ros2 service call /thermal/get_field_info \
  thermal_interfaces/srv/GetFieldInfo "{include_full_data: false}"
```

TF / 地图：
```bash
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo map base_link
ros2 topic echo /map --once
```

## 9. 手动驱动诊断（仅诊断 cmd_vel→odom 链路）

```bash
bash src/thermal_robot/scripts/send_cmd_vel.sh 0.2 0.3
# 或
ros2 topic pub --times 10 /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.1}, angular: {z: 0.0}}"
```
> 注意：控制器/Nav2 也在发 `/cmd_vel`，手动测会抢指令。仅用于排查移动链路，不作为正常控制方式。

## 10. 常见问题排查

| 现象 | 先查什么 |
|---|---|
| 某话题收不到消息 | **QoS 是否匹配**（sensor 类 BEST_EFFORT，结果类 RELIABLE）；发布者是否在 `ros2 node list` |
| RViz 不出现 | 是否 `use_rviz:=false`；是否等够 20s；`/rviz2` 是否在节点列表；`echo $DISPLAY`（SSH/容器） |
| 机器人不动 | 看 controller 日志 `[STATE]`；`/cmd_vel hz`；Nav2 是否 active（不 active 时应有直接兜底） |
| Nav2 报 "out of bounds of costmap" / "Cannot create a plan" | 已知问题（见 06）；控制器有直接 cmd_vel 兜底所以不会停死，但 Nav2 闭环不健康 |
| 改了代码不生效 | 是否重编 + 重新 `source install/setup.bash` |
| 改了 msg 后下游报错 | 先单独重编 `thermal_interfaces` 再编下游 |
| 找不到源/recall 低 | 跑 attribution 看是 not_reached/occluded/not_confirmed（见 04） |
| pytest 失败 | 看是不是改动破坏了某个 T-PY；纯算法层不依赖 ROS，应能直接定位 |

## 11. 实验数据目录（git 忽略）

- `bags/collected/<时间戳>/`：单次采集。
- `bags/matrix/<名字>/`：矩阵批量（含 `matrix_summary.json` + `matrix_report.md` + 每 run 子目录）。
- `bags/plots/`：旧绘图输出。
> `bags/` 体积大且被忽略，别提交进 git；要存基准数据请单独归档。

## 12. ⚠️ 不要做的事（继承自项目约定）

- 不要恢复已删除的旧文件（`sim_nav_launch.py`、`thermal_nav.rviz`、`plot_metrics.py`、`run_tests.sh` 等）。主线只有 `sim_nav_slam_launch.py`。
- 不要随便改 `use_sim_time`（当前 false）。要改必须同时验证 Gazebo `/clock`、TF、SLAM、Nav2 lifecycle、控制器时间戳（见 06）。
- 不要为单一 world/scenario 特化调参——新常数进 `params.yaml` 必须附跨 world 矩阵数据（设计文档风险 5）。
- 不要把热源真值坐标接进控制器（破坏通用性）。`/sim/thermal_sources_truth` 只给评测。
- 不要随意改话题/消息/频率（节点接口约束）；确需改动要说明兼容性与迁移。
