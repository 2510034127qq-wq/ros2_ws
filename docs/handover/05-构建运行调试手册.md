# 接手文档 05 · 构建运行调试手册

核对日期：2026-09-14。以下在工作区根目录执行，使用 ROS 2 Humble + Gazebo Classic。

## 构建和环境

```bash
cd /home/hanchen/ros2_ws
source /opt/ros/humble/setup.bash
rosdep check --from-paths src/thermal_robot --ignore-src
colcon build --packages-select thermal_interfaces
source install/setup.bash
colcon build --packages-select g1_description thermal_sensor_sim signal_preprocessor thermal_field_reconstructor thermal_gradient_processor thermal_motion_controller thermal_bringup
source install/setup.bash
python3 -m pytest src/thermal_robot/tests/ -q
```

以后每个新终端先 source `/opt/ros/humble/setup.bash` 和工作区 `install/setup.bash`。修改接口后先重建接口包再重建下游；修改源码 YAML 后重建 thermal_bringup。删除模块/场景后，旧 install 可能残留旧文件，应清理对应包产物再完整重建。验证 runner 会检查源/安装一致性。

## 启动仿真

```bash
ros2 launch thermal_bringup sim_nav_slam_launch.py use_rviz:=true use_gzclient:=true
```

无界面 B 级五源障碍场（与上面的仿真二选一）：

```bash
ros2 launch thermal_bringup sim_nav_slam_launch.py \
  use_rviz:=false use_gzclient:=false sensor_model:=b \
  strategy:=dual belief_mode:=online \
  world_file:=$PWD/src/thermal_robot/thermal_bringup/worlds/thermal_scene_obstacle_field.world \
  scenario_file:=$PWD/src/thermal_robot/thermal_bringup/config/scenarios/static_five_sources.yaml
```

主 launch 默认 A、dual、online、use_sim_time=true。场景与世界独立选择；动态场景字段会被拒绝。当前静态场景为 static_two_sources、static_five_sources、static_offset_sources、software_contract_multisource；空 scenario_file 使用默认 Config-B 三源布局。

```bash
ros2 launch thermal_bringup sim_nav_slam_launch.py --show-args
```

B 默认目标 0.3 m 宽、0.8 m 高、28–37℃恒定表面温度。修改 `multisource.yaml` 的 `source_temperature_range_c` 后重建；或复制完整文件到自定义路径修改并传 `software_params:=/绝对路径/配置.yaml`。该参数替换默认软件配置层，launch 内联覆盖仍有更高优先级。

## 启动后检查

热链路约 18 秒开始启动，RViz 约 20 秒开始启动；等节点与导航就绪再采集。

```bash
ros2 node list
ros2 action info /navigate_to_pose
ros2 lifecycle get /planner_server
ros2 lifecycle get /controller_server
ros2 lifecycle get /bt_navigator
python3 src/thermal_robot/scripts/nav2_health_check.py --timeout 20
python3 src/thermal_robot/tests/test_thermal_system.py --ros
```

逐条运行 `ros2 topic hz TOPIC`，观察后 Ctrl+C：`/sim/thermal_raw`、`/thermal/filtered`、`/thermal/field`、`/thermal/gradient`、`/thermal/map`、`/thermal/sources`、`/thermal/belief`（未 off 时）、`/odom`、`/scan`、`/cmd_vel`。A/B 图像标称 10/8.6 Hz，热地图上限 5 Hz，现代快层上限 2 Hz，慢层 1 Hz；输入和调度会影响实际频率。B 还要看 `/thermal/depth` 与 `/thermal/camera_info`。

```bash
ros2 service call /thermal/get_field_info thermal_interfaces/srv/GetFieldInfo "{include_full_data: false}"
ros2 run tf2_ros tf2_echo map base_link
ros2 topic info /thermal/map -v
```

仿真 odom 已是绝对世界位姿，不能再加出生点。Nav2/热控制使用不同坐标表示时由代码转换；显示错位先核对 TF、frame 与偏移。

## UGV / 回放

```bash
ros2 launch thermal_bringup ugv_thermal_launch.py
```

默认 enable_motion=false、use_sim_time=false。覆盖层不启动底盘、SLAM/Nav2；需外部提供测温图、CameraInfo、深度和标定 TF。Lepton/PT3 本身不是深度来源。详细输入类型见 [UGV 接入](../software/multisource_runtime.md)。

回放用 `ros2 bag play BAG --clock`，覆盖层设置 `use_sim_time:=true enable_motion:=false`；若 bag 已有 `/thermal/raw` 则加 `start_input:=false`，已有配准 `/thermal/depth` 则加 `register_depth:=false`。避免录包内派生热输出与覆盖层重复发布。启用运动属于实际设备调试，当前文档不表示已经完成实机验收。

## 停止和排错

正常在 launch 终端 Ctrl+C。若有当前工作区遗留的 Gazebo：

```bash
bash src/thermal_robot/kill_gz.sh
```

| 现象 | 排查方向 |
|---|---|
| 收不到图像/地图 | 节点、QoS、frame、输入时间戳；B 再查深度与内参 |
| 参数改了没效果 | install 是否重建/source；是否被 launch 内联参数覆盖 |
| 停车或只转向 | 扫视、无可行目标、scan 过期、障碍或延期日志；不能假定停住就是节点崩溃 |
| Nav2 action 结束但没接近 | 检查真实轨迹、abort/超时、停距与朝向；action 完成不代表巡检成功 |
| out of bounds / 无路径 | TF、SLAM 地图、costmap、机器人位置与规划容差；旧故障已修过，仍需当前日志判断 |
| 多个速度发布者 | 检查 controller/Nav2/手动输入；手动测试前停止自主命令源 |
| 检测数多但未搜齐 | 用真值匹配核对物理源、多标签、age、采样窗口和实际接近 |
| 消息字段不兼容 | 当前接口已删速度/重捕获/清场等字段，重编接口与消费者，优先回放原始消息 |

不要恢复旧非 SLAM launch、旧绘图入口或动态任务模块。运行时真值只供评测。生成数据、构建目录与缓存不提交；命令成功、单元测试通过和真实硬件可靠运行是不同验收层次。
