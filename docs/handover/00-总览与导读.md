# 接手文档 00 · 总览与导读

核对日期：2026-09-14，运行代码基线 `244d067`。本套文档解释当前实现，不把旧改版目标当作已经实现的能力。

## 项目做什么

机器人在 Gazebo 中探索障碍环境，观察**固定位置、持续发热**的物体，把热观测投影到地图并登记热源，尝试安全接近和停留。没有移动目标预测、生灭识别、自动搜完判定。已知源处理完仍继续探索。

主仿真是 ROS 2 Humble + Gazebo Classic + 简化差速 `g1_nav.urdf` + SLAM Toolbox + Nav2。完整 G1 资产仍在，但主线没有人形步态或 G1 SDK。另有面向外部 UGV 系统的热处理覆盖层，默认不启动运动控制器。

## 必须区分的概念

| 概念 | 当前含义 |
|---|---|
| A 级观测 | 64×48 理想俯视热场，默认 10 Hz |
| B 级观测 | 160×120 前视表面热图与深度，默认 8.6 Hz |
| Config-B | 默认三个静态源的场景布局；与 B 级传感模型是两个维度 |
| `/map` | SLAM 几何占据图；不能表示所有表面已经热观测 |
| `/thermal/map` | 温度、置信度、观测年龄和可见性状态的热栅格 |
| `/thermal/sources` | 快层登记表，candidate/confirmed；已确认 ID 在会话内保留 |
| `/thermal/belief` | 对登记源的慢后验，源数 PMF 不代表未知源已排除 |
| 发现 / 接近 | 真值匹配发现、控制日志确认、物理接近是分别验证的指标 |

默认启动选项为 `sensor_model:=a strategy:=dual belief_mode:=online use_sim_time:=true`。单独 `ros2 run` 不加载完整 launch 的参数覆盖，行为可能不同。
