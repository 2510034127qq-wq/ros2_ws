## 一句话：这个项目是什么

> 在 **ROS 2 Humble + Gazebo Classic** 仿真里，让一台简化的**宇树 G1 机器人**靠一台**热成像相机**，在不知道热源坐标的前提下，**自主探索并定位环境里的多个热源**，同时用 **SLAM 建图 + Nav2 导航**避障移动。

它是一个**研究型项目**，最终目标是发表论文 + 在真实宇树 G1 上落地。核心创新点在“**信念层 + 规划层**”——把多热源搜索建模成一个**概率推断问题**（详见 `06`）。

它**不是**一个产品，也**不是**只跑一次的 demo。它的价值在于：一套可复现的算法 + 一套能客观打分的评测体系。

## 给新手的概念扫盲（看代码前必须懂的词）

### ROS 2 基础

- **ROS 2**：机器人软件框架。把功能拆成一个个独立进程（叫**节点 node**），节点之间通过**话题/服务/动作**通信。
- **节点 (Node)**：一个独立运行的程序单元。本项目每个 `*_node.py` 就是一个节点（如 `sensor_node`、`controller_node`）。
- **话题 (Topic)**：单向广播式通信。一个节点**发布 (publish)** 消息到某个话题名（如 `/cmd_vel`），其他节点**订阅 (subscribe)** 来接收。异步、多对多。
- **消息 (Message, msg)**：话题上传输的数据结构。ROS 自带很多（如 `geometry_msgs/Twist` 速度指令、`sensor_msgs/Image` 图像）；本项目还自定义了几种（在 `thermal_interfaces` 包，如 `ThermalField`、`ThermalMap`）。
- **服务 (Service, srv)**：请求-应答式通信（像函数调用）。本项目只有一个 `/thermal/get_field_info`。
- **动作 (Action)**：长耗时任务的通信（可反馈进度、可取消）。本项目用 Nav2 的 `navigate_to_pose` 动作让机器人导航到某点。
- **QoS (Quality of Service)**：话题通信的“服务质量”策略，比如 `RELIABLE`（保证送达）vs `BEST_EFFORT`（尽力而为，丢了就丢了，适合高频传感器）。**收发两端 QoS 必须兼容，否则收不到消息**——代码里很多注释在强调这点。
- **launch 文件**：一次性按顺序启动一堆节点的脚本。本项目主线是 `sim_nav_slam_launch.py`。
- **参数 (Parameter)**：节点的可调配置项，集中写在 `params.yaml`，启动时注入节点。改行为优先改 YAML，不改代码。
- **TF (Transform)**：坐标系变换树。机器人有很多坐标系（地图 `map`、里程计 `odom`、机器人本体 `base_link`、相机 `thermal_camera`），TF 负责它们之间的实时换算。
- **colcon / 工作区 (workspace)**：`colcon build` 是 ROS 2 的编译命令。本工作区 = `/home/hanchen/ros2_ws`，源码在 `src/`，编译产物在 `build/` 和 `install/`（这两个被 git 忽略）。

### 仿真与导航

- **Gazebo Classic 11**：物理仿真器。负责模拟机器人在世界里的运动、激光雷达、里程计。
- **SLAM**：同步定位与建图。本项目用 `slam_toolbox`，吃激光 `/scan` + 里程计 `/odom`，吐出占据栅格地图 `/map` 和 `map→odom` 的 TF。
- **Nav2**：ROS 2 导航栈。负责“给个目标点，规划路径并控制机器人走过去（同时避障）”。本项目用它做大范围移动；近距离精细动作控制器自己直接发 `/cmd_vel`。
- **占据栅格 (OccupancyGrid)**：把世界离散成格子，每格标记“空闲/占据/未知”。
- **差速驱动 (diff drive)**：两轮独立驱动的运动模型。机器人靠 `/cmd_vel`（线速度 + 角速度）移动。

### 本项目特有概念

- **热源 (heat source)**：环境里发热的点，仿真里建模成**二维高斯**：中心温度 = 环境温 + 幅值 `amplitude`，按距离按 `sigma` 衰减。
- **热场 (thermal field)**：相机视野内每个像素的温度图（64×48）。
- **梯度上升 (gradient ascent)**：朝“温度上升最快的方向”走，就能爬到热源——近距离精确定位用这个。
- **世界热图 (ThermalMap / WorldThermalGrid)**：把每帧相机图像融合到一张**世界坐标系**的大网格里（50m×50m，0.25m/格），记录每格的平均温度、方差、置信度、访问次数、可见性状态。这是全局探索决策的依据。
- **源跟踪 (source tracking)**：从世界热图里检测热峰，用最近邻多假设跟踪器把它们维护成“候选源/确认源”，去重、确认。
- **可见性 (visibility)**：用 SLAM 地图做射线检测，判断某格是“没看过 / 看过但被墙挡住 / 看清了”。这是 phase 1 的核心新增。
- **残差场 (residual)**：实测温度 − 用已知源预测的温度。残差大的地方 = 可能藏着没发现的源。
- **清场概率 (clearance probability)**：用生成式概率模型估计“当前还有没发现的源”的概率，用来判断“搜完了没”。
- **状态机 (FSM)**：控制器的核心，11 个状态（探索/上升/收敛/采样/确认/离开…）之间切换。见 `03`。

## 一张图看懂全局（速览，细节见 `01`）

```
Gazebo 仿真 (g1_nav 机器人 + world)
   │  /scan(激光)  /odom(里程计)
   ▼
slam_toolbox ──► /map(占据栅格) + TF(map→odom)
   │
   ▼
Nav2 ◄──(navigate_to_pose 动作)── controller_node ──► /cmd_vel ──► Gazebo
                                       ▲   ▲   ▲
   热相机仿真链（决策的“眼睛”）：       │   │   │
sensor_node ─/sim/thermal_raw→ preprocessor ─/thermal/filtered→
   ├─► reconstructor ─/thermal/field→ gradient_node ─/thermal/gradient─┘（近距精细）
   └─► thermal_mapper ─/thermal/map→ source_tracker ─/thermal/sources──┘（全局决策）
```

- **两条感知链**：`/thermal/gradient`（瞬时、近距离梯度上升用）和 `/thermal/map`+`/thermal/sources`（累积、全局探索用）。
- **两套执行**：FINE 状态控制器直接发 `/cmd_vel`；COARSE 状态优先用 Nav2，失败兜底直接 `/cmd_vel`。
- **关键设计原则**：控制器**绝不**把热源真值坐标当输入（`/sim/thermal_sources_truth` 只给评测脚本用），导航完全由传感器信号驱动 → 保证算法通用性。
