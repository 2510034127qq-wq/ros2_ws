# 接手文档 04 · 评测体系与实验

> 本项目是研究型项目，**“算法能不能用”靠数据说话**。这套评测体系（phase 0 交付）是项目最有分量的工程资产之一。
> 本篇讲：怎么采集数据、怎么批量跑矩阵、怎么算指标、怎么做归因、怎么做统计检验、单测覆盖什么。

## 1. 评测的三个层次

```
单测 (pytest)         保证“算的对”      ── 纯 Python，无 ROS，秒级，86 个
  ↓ 全绿后才能
单次采集 (collect)     看“一次跑成啥样”   ── 启动仿真 → 采 CSV → 出图/算指标
  ↓
评测矩阵 (matrix)      证明“普遍用得好”   ── 多 world × 多 scenario × 多 seed 批量闭环
```

设计文档原则：**单测保证“算得对”，仿真矩阵保证“用得好”，仿真验证只在单测全绿后做**。

## 2. 核心指标（source_benchmark.py）

`scripts/source_benchmark.py` 从一次采集目录算源级指标：
- **recall（召回）** = 匹配上的真值源数 / 真值源总数。← 最核心，“找全了没”。
- **precision（精度）** = 匹配数 / 确认源总数。“确认的都对吗”。
- **duplicate_confirmations** = 确认数 − 匹配数。“重复确认了几个”（precision 杀手）。
- **time_to_first_source / time_to_all_sources**：首个/全部确认耗时。
- **localization_errors_m**：每个匹配源的定位误差。
- **path_length_m**：机器人走的总路程。

匹配规则：确认源与真值源最近邻配对，匹配半径 `max(2.0, 2*truth_sigma, 2*est_sigma)`（随源尺度缩放，见 T-PY27）。

## 3. 失败归因（attribution.py）— 项目的“上帝视角诊断”

`scripts/attribution.py` 对**每个没找到的真值源**分类失败原因（用真值占据栅格做视线判断）：

| 类别 | 含义 |
|---|---|
| `not_reached` | 从没进过相机 FOV（机器人压根没走到附近） |
| `occluded` | 进过 FOV 但被墙挡住，没看清 |
| `not_confirmed` | 看清了（累计可见 ≥1s）但没确认（算法保守/卡住） |
| `timing_missed` | 进 FOV 时源恰好不活跃（动态生灭源错过时机） |

**这是 phase 0 最重要的产出**。phase 0 全量矩阵（120 局）实测发现：**漏检源 100% 是 `not_reached`**（186/186 个漏源从没进 FOV，最近接近距离中位数 5.8m）。结论：**瓶颈是“覆盖/走到”，不是“看清/确认”**——直接决定了 phase 1 优先做覆盖相关的可见性/残差探索。

> 这条结论彻底改变了开发方向，是“用数据驱动决策”的范本。新手务必理解：不要凭直觉猜算法哪里差，跑归因看数据。

## 5. 评测矩阵（run_multiscenario_matrix.py）— 批量闭环

核心评测工具。对每个 (world, scenario, seed) 组合：启动一次无头仿真 → warmup → 跑 collector → 自动算 source_summary + attribution → 判 PASS/FAIL。

```bash
python3 src/thermal_robot/scripts/run_multiscenario_matrix.py \
  --preset phase0 --seeds 101,102,103,104,105 \
  --strategy full --duration 120 --warmup 36 \
  --domain-start 71 --out-root bags/matrix/<名字>
```

### 5.1 预设 (`--preset`)
- `phase0`：**4 类 world × 6 类 scenario = 24 用例**（主力门槛矩阵）。
  - world：open / boxes / walls / mixed。
  - scenario：static2 / static3(Config-B) / static5 / dyn4 / dyn5 / birthdeath。
- `representative`（4）/ `extended`（6）/ `variable`（3，2/4/5 源）/ `full`（6 world × 9 scenario = 54）。
- 也可 `--case name:world_path:scenario_path` 单独指定。

### 5.2 隔离机制（避免并行串台）
每个 run 独立：`ROS_DOMAIN_ID`、`GAZEBO_MASTER_URI`（端口 11345+domain）、临时 `HOME`、本地 `GAZEBO_MODEL_PATH`、`ROS_LOG_DIR`。可借 `--domain-start` 并行多个无头实例。

### 5.3 PASS 判据
`collector returncode==0` 且关键话题计数都 >0 且 `recall >= --min-recall` 且 `duplicate_confirmations == 0`。

### 5.4 子集筛选
`--worlds open,boxes`、`--cases open__static5,walls__static5`、`--seeds 101,102`。日常迭代跑子集，门槛跑全量。

### 5.5 产物
`<out-root>/matrix_summary.json`（全部 run 原始数据 + 聚合）+ `matrix_report.md`（人读报告，含每用例多 seed 均值±std + 失败归因表）。

## 6. 统计（matrix_stats.py）

phase 1 补齐的统计工具：
- `aggregate_case_runs`：多 seed 均值/std/min/max。
- `mann_whitney_u`：两组非配对秩检验（小样本走精确枚举，大样本正态近似带连续性校正）。
- `paired_permutation_test`：**配对**符号翻转置换检验（同 case+seed 配对，是主检验）。
- `cluster_bootstrap_ratio_ci`：以 run 为重抽样单位的事件汇总比率 95% CI（precision/duplicate 验收口径，杜绝口径之争）。
- `render_markdown_report`：渲染矩阵报告。

`matrix_compare.py`：对比两个 out-root（如新算法 vs v31 锚点），输出配对检验 + CI。

## 7. 真值占据栅格（world_occupancy.py）

`scripts/world_occupancy.py` 解析 `.world` SDF 里的 box 碰撞体，栅格化成真值占据图（0.1m/格，只算 z∈[0.15,1.5] 的障碍），存到 `worlds/occupancy/<world>.npz`。归因脚本用它做视线（line_of_sight）判断“源是不是被墙挡了”。几何常数与在线热图共用 `grid_geometry.py`。

```bash
python3 src/thermal_robot/scripts/world_occupancy.py \
  --worlds-dir src/thermal_robot/thermal_bringup/worlds \
  --out-dir src/thermal_robot/thermal_bringup/worlds/occupancy
```

## 8. Nav2 健康检查（nav2_health_check.py）

`run_multiscenario_matrix.py --health-only` 会跑它，检查 Nav2 lifecycle/action/plan 是否健康，记录每局 Nav2 可用率（应对“障碍世界 Nav2 不稳”风险）。

## 10. 已跑过的实验结论（devlog 摘要）

按时间在 `docs/devlog/`，重要里程碑：
- **phase0 全量矩阵（06-12, 0141）**：120 局（24 用例 × 5 seed，5.35h）。结论：漏检 100% not_reached；dyn4 有 8/20 局重复确认（precision 0.75）；mixed world Nav2 无 /plan。
- **phase1 残差全量矩阵（06-13, 0219）**：残差策略 vs full 的配对对比。
- **phase1 覆盖墙诊断（06-13, 1421，最新）**：固定 strategy=full，在 static5 上扫 duration（120/240/360s）。结论：**recall 瓶颈是覆盖而非观测质量**——延长时间 recall 没本质改善（仍 ~0.4），漏源最近距离中位数 5.7~6.2m。这是当前**待攻克**的核心问题。

> 早期 devlog（05-02 系列）记录了 v31 时代的多 world 泛化、单源扇扫、变源数等实验，反映了从 v31 到概率重构前的演进。

## 11. 验收门槛（设计文档 §2）

最终论文级验收标准（不是逐局硬指标，是统计口径）：
1. 多 world 矩阵多 seed recall **显著优于** v31 锚点和纯 frontier/levy 基线（配对检验 p<0.05）。
2. precision 95% 置信下界 ≥ 0.90，duplicate rate 显著低于 v31。
3. 清场概率可校准：ECE ≤ 0.10。
4. 每决策周期 CPU ≤ 100ms（板载预算）。
