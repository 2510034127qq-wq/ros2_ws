## 独立软件闭环

停止其他仿真，用新输出目录运行：

```bash
python3 src/thermal_robot/scripts/run_software_validation.py \
  --out bags/software_validation/my_static_b --sensor-model b \
  --strategy dual --belief-mode online --scenario static_two_sources.yaml \
  --duration 90 --seed 101 --domain 151
python3 src/thermal_robot/scripts/evaluate_detection_tracks.py bags/software_validation/my_static_b
python3 src/thermal_robot/scripts/plot_software_validation.py   bags/software_validation/my_static_b --out /tmp/static_b.png
```

runner 自行启动仿真，默认预热 36 秒，检查源码/install 一致性，用锁串行化 Gazebo，并保存输入、运行日志、probe 和探测结果。预热与采样窗口不是一回事。用 `--world` 换几何，`--software-params` 替换软件配置层，`--expected-health over_budget` 配合预算注入验证降级。

`probe_software_stack.py` 检查消息、深度、热图、位移、慢层健康等；通过 probe 只说明这些运行条件满足。`evaluate_detection_tracks.py` 按默认 age ≤1.5 秒、confirmed、距真值 ≤1 m、次近源至少多 0.2 m、至少 3 次有效匹配统计窗口发现数，另报多标签、身份切换、未匹配记录和定位误差。只在已匹配样本上算的误差不能代替所有误报/漏报指标。

该离线脚本仍可分析旧结果中的 inactive 物体，不表示当前模拟器支持动态生灭。控制器 `[SURFACE_CONFIRMED]` 也不是物理真值证明；严格接近评估需要机器人真实位姿、时间对齐、物理源匹配、距离/朝向/停留核对。

## 静态矩阵与统计

```bash
python3 src/thermal_robot/scripts/run_multiscenario_matrix.py \
  --preset phase0 --cases open__static5,walls__static5 \
  --seeds 101,102 --strategy dual --duration 120 --warmup 36 \
  --out-root /tmp/quick_static_matrix
```

当前 `phase0` 是保留的预设名字，含 4 个 world 类（open/boxes/walls/mixed）× 3 个静态布局（static2/static3/static5）= 12 个用例；并非旧 24 用例动态矩阵。另有 representative/extended/variable/full 预设，世界文件总计 6 个。runner 默认 strategy 是 full，与主 launch 默认 dual 不同。

此脚本没有 `--sensor-model`，沿用主 launch 默认 A。B 级测试用软件验证 runner。矩阵对 fast/dual/gp_ucb 显式启用仿真时钟，对旧策略保留 false，比较时必须把时钟差异记录为实验条件。

`matrix_stats.py` 提供汇总、配对/非配对检验与 bootstrap；`matrix_compare.py` 比较报告。`attribution.py` 的到达/遮挡诊断仍依赖 A 级 4×3 m 足迹假设，不能解释 B 前视相机全部漏检机制。旧 `phase1_gate.py` 和清场校准工具已删除，不再提供旧研究门槛的当前执行入口。
