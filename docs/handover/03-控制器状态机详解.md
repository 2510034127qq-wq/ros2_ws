# 接手文档 03 · 控制器状态机详解（controller_node v31）

> `controller_node.py`（2303 行）是项目的决策大脑，也是最难读的文件。本篇拆解它。
> 建议：先读 `01`（数据流）和 `02` 的“包 7”概述，再读本篇。

## 0. 心法：先理解“分层”

控制器把职责分成三层（文件头注释也写了）：

```
任务策略层  target_selection.py（SourceSeekTargetSelector）
            └ 决定“去哪”：frontier / coarse waypoint / departure / escape 方向
                ↓ 返回 StrategyTarget（目标点 + reason + 执行偏好）
执行层      controller_node.py（本文件）
            └ 决定“怎么走 + 何时切状态”
                ├ FINE 状态：直接发 /cmd_vel（梯度上升类精细动作）
                └ COARSE 状态：优先 Nav2 动作，失败/卡住兜底直接 /cmd_vel
```

**核心原则**：控制器永远不知道热源真值坐标。一切由 `/thermal/gradient`（瞬时近距信号）、`/thermal/map` + `/thermal/sources`（累积全局信念）驱动。

## 1. 11 个状态

```python
# FINE（精细，直接 /cmd_vel）
ASCENT      梯度上升：朝温度上升方向走
CONVERGE    收敛：靠近源做精细逼近（含“黏性”反复回到最热点）
SAMPLE      采样：停下，连续测温确认是不是真源
AT_PEAK     到顶：确认后短暂停留
RELOCATE    重定位：离开已确认源的排斥区（旧路径，现在多被 immediate departure 取代）
ESCAPE      逃逸：卡住/进排斥区/丢信号时的恢复

# COARSE（粗放，Nav2 优先 + 直接兜底）
FRONTIER_NAV   前沿导航：大范围信息增益探索（★初始状态★）
COARSE_SURVEY  系统巡航：冷场时的覆盖式搜索，周期性停下感知
SURVEY_PAUSE   巡航暂停：停下 sense 几秒判断要不要进 FINE
DEPARTURE      离开：确认源后直接朝远处目标移动（不走 Nav2，目标常在地图外）

# 终止
DONE        所有源找完 / 长时间无新源
```

常量分组：`COARSE_STATES = {DEPARTURE, COARSE_SURVEY, FRONTIER_NAV}`、`FINE_STATES = {ASCENT, CONVERGE, SAMPLE, RELOCATE, ESCAPE, AT_PEAK}`。

**初始状态是 `FRONTIER_NAV`**（不是从静止开始找，而是直接开始大范围探索）。

## 2. 典型生命周期（一次成功找源）

```
FRONTIER_NAV ──(冷场 >32s)──► COARSE_SURVEY ──(周期)──► SURVEY_PAUSE
   │  探索中检测到热信号 trise↑                            │ sense 到信号
   ▼                                                       ▼
FRONTIER_NAV/ASCENT（梯度上升靠近）                    回 FRONTIER_NAV
   │  trise 达到 pre-peak 阈值
   ▼
CONVERGE（精细逼近最热点，可“黏性”多次回到全局最热）
   │  trise 达 sample 阈值 + 热点在视野中心 / tracker 源就绪
   ▼
SAMPLE（停 3s 连续测温）
   │  top-80% 平均 trise >= sample_min_trise 且有 tracker 源估计够近
   ▼  ★ 记录 tracker 源位置（不是机器人位置）为确认源 ★
AT_PEAK（停留 peak_hold_s）
   │  还要找更多源
   ▼
DEPARTURE（直接朝远处目标走，离开当前源排斥区）
   │  到达/超时
   ▼
COARSE_SURVEY → ... 继续找下一个源
```

直到 `(now - last_found_t) > no_new_source_timeout`（默认参数 180s，注意 `params.yaml` 注释提到曾用 60s）→ `DONE`。

## 3. 主循环：`_timer_cb()`（10Hz，行 ~2046）

每个 tick 的处理顺序（**顺序即优先级**）：

1. 更新位姿：`_update_world_pos_from_tf()`（算 world 坐标 + 累计路径长）。
2. `_update_armed(T)`：温度降下来后重新“武装”峰检测（避免在同一源反复触发）。
3. **DONE 检查**：已 DONE 则发零速返回；开放式 `num_sources<0` 且超时无新源 → DONE。
4. **按状态分派**（每个 `if state==... : return`）：
   - SAMPLE → `_exec_sample`
   - CONVERGE → `_exec_converge`
   - AT_PEAK → 停留计时，到点后转 RELOCATE 或直接 departure（`post_confirm_immediate_departure=true` 时）
   - SURVEY_PAUSE → `_exec_survey_pause`
   - COARSE_SURVEY → `_exec_coarse_survey`
   - DEPARTURE → `_exec_departure`
   - RELOCATE / ESCAPE → 内联处理
5. **ACTIVE 状态（ASCENT/FRONTIER_NAV）的安全检查**（按序）：
   - `_check_stuck`（卡住）→ ESCAPE
   - 进入已确认源排斥区 → ESCAPE
   - `_check_thermal_lost`（丢热信号）→ ESCAPE(centroid_return)
   - `_check_radius_overflow`（离质心太远）→ ESCAPE(centroid_return)
   - FRONTIER_NAV 冷场计时 → COARSE_SURVEY
   - `_should_enter_converge()` → CONVERGE
   - `_should_ascent(gm)` → ASCENT（梯度上升）
   - 否则 → FRONTIER_NAV：refresh frontier 目标 + Nav2 + 兜底直接 cmd_vel
6. 每 ~5s 打印状态日志（`[STATE] t=... world=... T=... nav2=... found=...`）。

> 读代码技巧：从 `_timer_cb` 开始顺着 `return` 往下读，每个 state handler 是独立的 `_exec_*` 方法。

## 4. 关键判定函数

| 函数 | 作用 |
|---|---|
| `_grad_mag()` | 取梯度数组中前 30% 最大幅值的均值（抗噪） |
| `_temp_rise()` | 当前峰温 − 环境温估计 |
| `_should_ascent(gm)` | 梯度够大且 trise 够（进入/维持 ASCENT 的迟滞阈值） |
| `_should_enter_converge()` | trise 达 pre-peak 阈值，且不在已知源附近、不在确认冷却期、梯度不指向已知源 |
| `_check_peak_sample_v22(now)` | SAMPLE 结束判定：缓冲区 top-80% 平均 trise ≥ sample 阈值 |
| `_tracker_source_ready_for_sample(est,...)` | tracker 源够可信（概率≥0.75、观测≥5、够近）才允许确认 |
| `_is_peak_near_fov_center()` | 最热像素是否在视野中心 12 像素内（判断是否对准了源） |
| `_adapt_pk_delta()` 等 | **自适应阈值**：弱源时按已观测最大升温自动放低确认门槛（`adaptive_thresholds_enabled=true`） |

## 5. 源确认：用 tracker 估计，不是机器人位置（重要）

`_exec_sample`（行 ~1987）确认源时（注意 `controller_node.py:1996` 一带）：
```python
est = self._best_tracker_source_for_sample()   # 从 /thermal/sources 里挑最佳候选
if est is not None and not near_known:
    self._found_sources.append((est['x'], est['y'], T))   # ★ 记 tracker 估计位置 ★
    self._bmap.mark_excluded / suppress_confirmed_source   # 在 belief map 标排斥区
    state = AT_PEAK
    self._pc_guard_t = now + post_confirm_cooldown_s       # 一段时间内禁止再 CONVERGE
    self._pc_rounds_left = post_confirm_rounds             # 之后若干轮强制远场探索
```
**为什么用 tracker 位置而不是机器人位置**：机器人停的地方不等于源中心；tracker 通过多帧融合给出更准的源质心估计。若没有够近的 tracker 估计 → 拒绝确认，回 FRONTIER_NAV。这是 precision 的关键保障。

## 6. 确认后的“离开”机制（避免反复确认同一个源）

历史上最大的 bug 类别是“反复在第一个源附近打转，永远找不到 SB_far/SC_weak”。现在的对策（多层）：
- **post-confirm guard**：确认后 `post_confirm_cooldown_s` 内不准再进 CONVERGE（`_pc_guard_t`）。
- **post-confirm boost**：之后 `post_confirm_rounds=10` 轮 frontier 强制 `min_d=7m`、`dist_sigma=15m`（推向远场）。
- **immediate departure**：`post_confirm_immediate_departure=true` 时，AT_PEAK 后直接进 DEPARTURE，朝远离已确认源质心的方向走。
- **多源扇区扫掠**（`target_selection.py`）：≥2 源后，沿“源对横向 / 源间缺口 / 向外”方向扇形扫掠，避免坍缩成单一半平面搜索。
- **belief map suppress**：确认源附近 `visit_count` 加 5000，让 frontier 打分器永远不再选那里。

## 7. Nav2 集成与“直接兜底”

控制器是 Nav2 `navigate_to_pose` 的 **ActionClient**。关键方法：
- `_check_nav2_ready()`：探测 action server 是否在（3s 一次）。
- `_send_nav2_goal(tx,ty)`：把 world 目标转成 `map` 系发给 Nav2（限频 3s 一次）。**返回 False 直到 goal 被 accept**——所以发完这一 tick 仍要兜底移动。
- `_nav2_goal_response_cb` / `_nav2_result_cb`：状态机 idle→sending→active→done。
- `_nav2_progress_stalled(...)`：Nav2 接了 goal 但 `nav2_progress_timeout_s=4s` 没进展 → 取消 Nav2，转直接 cmd_vel `nav2_stall_direct_s=16s`。
- `_cancel_nav2_goal()`：进 FINE 前取消 Nav2。

**设计哲学**：Nav2 优先（会避障、走得稳），但**永远有直接 `/cmd_vel` 兜底**保证机器人不会因为 Nav2 不健康而停死（FIX-2/FIX-4）。COARSE_SURVEY 和 FRONTIER_NAV 每 tick 末尾都有“若 nav2 非 active 则直接朝目标走”的逻辑。DEPARTURE **完全不用 Nav2**（目标常在 SLAM 地图外）。

## 8. 探索策略：strategy 参数（基线挂架）

`strategy ∈ {full, frontier, levy, residual}`（默认 full）。这是**评测基线挂架**（见 `04`）：
- `full`：完整算法（信息增益 frontier + 覆盖环 + 多源扫掠 + levy 兜底）。
- `frontier`：纯前沿基线。
- `levy`：纯 Lévy flight 随机游走基线。
- `residual`：phase1 残差探索 + 清场概率评估（`_residual_waypoint` / `_evaluate_clearance`，发 `/thermal/clearance`）。

`_refresh_frontier` / `_coarse_waypoint` / `_do_levy_jump` 内部按 strategy 分派到不同目标选择。

## 9. belief map（旧的内部信念图，与世界热图并存）

`ThermalBeliefMap`（行 ~120）是控制器**自带的**一个 0.5m/格、50m 网格，记录 visit/tmax/cold/excl。它早于 `WorldThermalGrid` 存在，现在作为**热图不可用时的兜底**（`_map_available()` 为假时用它的 `best_frontier`/`region_novelty`）。当 `/thermal/map` 正常时，新代码优先用世界热图。
> 新手注意：项目里有**两个**“地图/信念”概念——`thermal_mapper` 发的 `WorldThermalGrid`（主）和控制器内的 `ThermalBeliefMap`（兜底）。别混淆。

## 10. ESCAPE 的两种模式

- `EMODE_SOURCE_AVOID`：朝排斥方向逃（远离已知源），带循环检测（短时间内逃太多次 → 强制 Lévy 跳）。
- `EMODE_CENTROID_RET`：朝已确认源质心返回（丢信号/越界时用，把机器人拉回有信号的区域）。

## 11. 参数从哪来

控制器在 `__init__` 声明了 **~120 个参数**（`controller_node.py:243` 起一大片 `declare_parameter`），全部默认值可被 `params.yaml` 的 `controller_node:` 段覆盖。改行为**先改 YAML**。重要参数分组：
- 速度/转向：`max_linear_vel=0.28`、`max_angular_vel=0.5`、`kp_angular`。
- 峰检测/确认：`peak_temp_delta`、`sample_min_trise=8`、`tracker_verify_*`、`adaptive_thresholds_enabled`。
- 探索：`frontier_*`、`levy_*`、`coverage_ring_*`、`source_set_*`。
- 确认后：`post_confirm_*`、`departure_*`。
- Nav2：`nav2_progress_*`、`nav2_stall_direct_s`。
- 清场：`clearance_*`。

> `params.yaml` 头部注释（v26）记录了一段经典调参史：以前 `dist_sigma=8` 导致机器人困在第一个源 3-6m 环里，引入 `post_confirm_rounds` 等修复。读这段能快速理解“为什么有这么多确认后探索参数”。
