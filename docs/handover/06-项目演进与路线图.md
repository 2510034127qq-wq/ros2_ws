# 接手文档 06 · 项目演进与路线图

> 理解一个项目的“现状”，要知道它“从哪来、要到哪去”。本篇梳理历史、当前阶段、已知问题与坑。
> 权威依据：`docs/superpowers/specs/2026-06-10-thermal-multisource-program-design.md`（设计基准）+ devlog + git 历史。

## 1. 项目从哪来（背景）

来自 `项目初步介绍`（2026-04-29 立项说明）：
- 目标：基于**宇树 G1** 的温度传感与热导航，最终实机落地。
- 仿真选型：**Route A**（纯 Python 数学热场生成）。理由：算法验证不需要物理热耦合 + 规避 Gazebo 版本地雷 + 确定性 pytest + sensor_node 接口固定可后期替换为真实相机。放弃了 Route B（gz-sensors 插件）和 Route C（C++ 插件）。
- 机器人：为避免完整人形动力学/关节控制的复杂度，用简化 `g1_nav.urdf`（差速底盘）替代真 29-DOF G1。完整 G1 资产保留为将来用。
- 路线：先做感知/场重建/梯度上升/热导航/可视化 → 加障碍/避障 → 接 G1 SDK 实机。

## 3. 当前阶段定位

**phase 1 已交付，正处于 phase 1 门槛评审 / 向 phase 2 过渡**。最新 devlog 揭示的核心结论：

> **覆盖墙（coverage wall）**：static5 等场景 recall 卡在 ~0.4，延长 duration（120→240→360s）不改善，漏源最近接近距离中位数 5.7~6.2m。即“机器人走不到那些源附近”，不是看不清/不敢确认。

这是接手后**最值得关注的开放问题**。

## 4. 完整阶段计划（设计文档 §4）

| 阶段 | 内容 | 状态 |
|---|---|---|
| **0 评测地基** | 矩阵 runner + 归因 + 障碍世界 + 基线挂架 | ✅ 完成并过门槛 |
| **1 遮挡观测 + 残差 + 清场 v1** | 可见性/三态融合/残差/清场/配对统计/相机选型 | ✅ 已交付，门槛评审中 |
| **2 动态源跟踪 + 重访调度** | track 升级常速 Kalman[x,y,vx,vy]；revisit.py 重访队列 | ⬜ 未开始 |
| **3 慢层信念（候选方案制）** | 默认 Rao-Blackwell 源簇；备选变维粒子滤波（2 周击杀条件）；影子模式 | ⬜ 未开始，技术风险最高、主线依赖最低 |
| **4 论文级实验** | 全基线对比（+GP-UCB 强基线）、消融、校准曲线、传感器退化敏感性 | ⬜ 未开始 |

**重要声明**：设计文档明确“**phase 1+2 完成即构成完整可发表工作**”；phase 3（慢层）是增量贡献而非依赖项。

### sim-to-real 保真度阶梯（与各阶段并行）
- **A 级（现状）**：理想俯视足迹直读地面场（当前 sensor_node）。
- **B 级（phase 2-3 建设）**：场景放三维热表面物体，渲染前视透视热图 + 噪声/偏置/emissivity 扰动；观测前端从热像素提检测。
- **C 级（硬件到位后）**：真实热相机录包离线回放。触发条件 = 相机采购（选型文档已备，见 `docs/hardware/`）。
- **G1 集成（收尾）**：Unitree SDK 运动接口替换 diff-drive。**当前控制器不得新增绑死 diff-drive 假设的逻辑**。

### 两层表示声明（重要概念）
- **观测 = 表面辐射采样**（真实长波红外相机看不到空气温度，只看视线内表面辐射）。
- **信念 = 地平面源地图**（源质心地面投影 + 强度 + 范围，是**信念表示，不是物理场声明**）。
- A 级仿真的“地面温度场”是该表示在理想俯视下的退化情形。实机化只换观测前端，信念层/规划层/FSM 不依赖“场”假设。

## 5. 已知问题与坑（接手必读）

### 5.1 Nav2 costmap/map 边界问题（最重要）
障碍世界里偶发：`Robot is out of bounds of the costmap`、`Cannot create a plan`、`Planning algorithm GridBased failed`、mixed world 无 `/plan`。
- **缓解（已做）**：global_costmap 去掉 static 层、改用 rolling_window 60×60 + 只 obstacle/inflation；控制器全程有直接 `/cmd_vel` 兜底，所以机器人不会停死。
- **未根治**：Nav2 全局规划闭环仍不健康。设计文档把它列为 phase 0+ 持续风险（每局记 Nav2 可用率，可降级为直线无碰检查）。

### 5.2 Nav2 BT XML 路径
`navigate_to_pose_simple.xml` 现由 launch 用 package share 动态注入（已修可移植性，见 T-PY29）。`nav2_params.yaml` 里保留的是可读默认值，不再绑死本机 install 绝对路径。

### 5.3 use_sim_time = false
当前 Gazebo/SLAM/Nav2 统一用墙钟（不是 Gazebo 常见默认）。Nav2 goal 用 `stamp=0`（请求最新 TF）绕开了时间不一致。**改成 true 前必须一起验证** `/clock`、TF、SLAM、Nav2 lifecycle、Gazebo 插件时间戳。

### 5.4 reconstructor 退出风格不一致
`reconstructor_node` 退出直接 `rclpy.shutdown()`，与其它节点 `try_shutdown()` 不同，Ctrl-C 后可能二次 shutdown 异常。不影响算法，污染日志。

### 5.5 两套“地图/信念”并存
`thermal_mapper` 的 `WorldThermalGrid`（主，0.25m）与控制器内 `ThermalBeliefMap`（兜底，0.5m）共存。新代码优先用前者，后者仅 `/thermal/map` 不可用时用。改探索逻辑时注意别只改一个。

### 5.6 文档时间戳分裂
`PROJECT_ANALYSIS_REPORT.md`（04-27）和 `CLAUDE.md` 部分过时（见 `00` 的可信度表）。以 `src/README.md` + spec + 最新 devlog + 源码为准。

### 5.7 完整 G1 资产去留未定
`g1_description` 里 163 个 STL + 完整 URDF/xacro 体积大、当前主线不用。是否归档待项目目标明确后定。

## 6. 接手后建议的入手顺序

1. **跑起来看一眼**（`05`）：完整 GUI 仿真 + RViz，观察机器人探索/确认行为，建立直觉。
2. **读评测**（`04`）：跑一次 phase0 子集矩阵 + 看 `matrix_report.md` 和 attribution，理解“现在差在哪”（覆盖墙）。
3. **精读控制器**（`03`）：顺一条“找到一个源”的完整状态路径。
4. **读 spec**：`docs/superpowers/specs/2026-06-10-...md`，理解概率主线的终态架构与各阶段门槛。
5. **读最新 devlog**：`2026-06-13-1421-phase1-coverage-wall-diagnosis.md`，理解当前攻坚点。

## 7. 如果要继续推进（方向参考，非指令）

基于设计文档与最新诊断，自然的下一步：
- **优先攻“覆盖墙”**：漏源都是 not_reached，说明探索/覆盖策略没把机器人带到远源附近。可从 `target_selection.py` 的覆盖环/扇区扫掠 + `planning.py` 残差目标的 `min_d/max_d/旅行代价权重` 入手；用 phase0 矩阵 + 归因验证“not_reached 占比是否下降”。
- **phase 2**：动态源常速 Kalman + 重访队列（`revisit.py` 待建，spec §4 有契约）。
- 任何改动遵循：**先 spec→plan→TDD 单测→子集矩阵→全量矩阵门槛**，新常数附跨 world 数据，现有 86 测试保持全绿。
